# E2E-тесты (Playwright)

Ключевые сценарии в настоящем браузере (Chromium Playwright, безголовый режим).
Один раз установите браузер: `npx playwright install chromium`
(или используйте установленный Google Chrome: `E2E_CHANNEL=chrome npm run test:e2e`).

| Файл | Что проверяет |
|------|---------------|
| `guest.spec.ts` | главная без входа, окно входа/регистрации, ошибка неверного пароля, шаблоны без входа, редиректы старых адресов, 404 |
| `auth.setup.ts` | вход тестовым аккаунтом через интерфейс (сессия сохраняется в `e2e/.auth/`) |
| `dashboard.spec.ts` | проект из шаблона, избранное, теги и поиск, папки, удаление с подтверждением, вид списком, настройки и тема |
| `editor.spec.ts` | размещение мебели кликом в 3D (на полу, внутри комнаты), отмена/повтор, 2D-план со стенами, автосохранение и восстановление; от первого лица перетаскивание осматривает и не двигает стены и двери, клик выделяет перегородку и открывает дверь |
| `floors.spec.ts` | второй этаж, лестница из каталога, мебель наверху (не в проёме), всё на месте после перезагрузки; от первого лица по лестнице на второй этаж (он становится активным); режим «Улица»; старый одноэтажный проект (документ v3) открывается как один этаж без потерь |
| `cushions.spec.ts`, `mounts.spec.ts` | подушка садится на диван; постер вешается на стену, люстра — под потолок |
| `password-reset.spec.ts` | «Забыли пароль?» на своём новом аккаунте (регистрация через API): код из письма — из лога бэкенда, неверный код — ошибка по-русски, верный код и новый пароль; старая сессия и старый пароль больше не работают, вход с новым паролем — работает |

## Запуск

1. Запустите бэкенд (порт 8080) — `./run.sh` или `go run ./cmd/server` в `backend/`.
2. Создайте тестовый аккаунт на **локальном** бэкенде и запишите его в `e2e/.env.e2e.local`
   (файл в `.gitignore`, не коммитьте его):

   ```
   E2E_EMAIL=...
   E2E_PASSWORD=...
   ```

3. Для сценария сброса пароля бэкенд должен работать в режиме `SMTP_LOG_ONLY=true` (коды
   печатаются в лог, строка `[CODE]`), а путь к его логу — быть в `E2E_BACKEND_LOG`, например:

   ```bash
   (cd backend && SMTP_LOG_ONLY=true go run ./cmd/server > ../.run/backend.log 2>&1 &)
   E2E_BACKEND_LOG=.run/backend.log npm run test:e2e
   ```

   С бэкендом в Docker (`./run.sh`) лог можно писать так:
   `(cd backend && docker compose logs -f backend > ../.run/backend.log &)`.
   Без `E2E_BACKEND_LOG` сценарий сброса пароля пропускается; общий тестовый аккаунт он
   не трогает — заводит свой.
4. `npm run test:e2e` — дев-сервер поднимется сам (или используется уже запущенный на :3000).
   Против другого стенда: `E2E_BASE_URL=https://staging.example.com npm run test:e2e`.

Отчёт: `e2e/report/index.html`, трассировки упавших тестов — `e2e/results/` (`npx playwright show-trace …`).
Тесты создают проекты с префиксом «E2E» и удаляют их за собой.

В CI (GitHub Actions) тестовый аккаунт создаётся автоматически: бэкенд запускается в режиме
разработки, код подтверждения берётся из его лога — см. `.github/scripts/e2e-account.sh`;
тот же лог получает сценарий сброса пароля (`E2E_BACKEND_LOG` в `.github/workflows/ci-cd.yml`).
