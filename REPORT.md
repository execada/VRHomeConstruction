## 1. Сборка и тулинг

### 1.1 Артефакты компиляции в исходниках
- **Проблема:** `tsconfig.json` не содержал `noEmit`, поэтому `tsc -b` (вызывается в `build`) эмитил **128 `.js`-файлов прямо в `src/`** рядом с исходниками. Это засоряло дерево и создавало риск двусмысленного резолвинга модулей.
- **Исправление:** добавлен `"noEmit": true` в `tsconfig.json`; удалены все 128 стрэй-`.js`/`.js.map` и устаревший `tsconfig.tsbuildinfo`. `tsc` теперь только проверяет типы, бандлинг делает Rsbuild.

### 1.2 Скрипты `package.json`
- **`build`:** было `tsc -b && rsbuild` — а `rsbuild` без подкоманды по умолчанию запускает **dev-сервер**, то есть «сборка» вообще не собирала прод. → `tsc -b && rsbuild build` + добавлен `prebuild`, генерирующий список моделей.
- **`preview`:** было `vite preview` (проект на Rsbuild, не Vite) → `rsbuild preview`.
- **`dev`:** `rsbuild` → `rsbuild dev` (явно).

### 1.3 ESLint
- **Проблема:** установлен ESLint 9, но **нет flat-config** (`eslint.config.js`) — `npm run lint` падал с ошибкой.
- **Исправление:** добавлен `eslint.config.js` (flat config) с `@eslint/js`, `typescript-eslint`, `react-hooks`, `react-refresh`. Прогнал линт, **починил 2 ошибки** и убрал мёртвые импорты/переменные. Осталось 12 безобидных предупреждений (параметры reducer-триггеров RTK, один неиспользуемый проп, один `exhaustive-deps`).

### 1.4 SCSS
- Заменён устаревший `darken()` на `color.adjust()` (`UniversalButton.module.scss`) — Sass-deprecation, ломающийся в Dart Sass 3.

## 2. Бэкенд (Go)

### 2.1 Мультитенантность папок и макетов (безопасность)
- **Проблема:** маршруты `/api/folders` и `/api/layouts` **не были за auth-middleware**, а хендлеры использовали захардкоженный `defaultUserID = "user-1"`. В итоге **все пользователи видели и редактировали общие папки/макеты**.
- **Исправление:**
  - В `cmd/server/main.go` группы `folders` и `layouts` перенесены в `protected`-группу с `middleware.Auth`.
  - `userID` проброшен из контекста токена в хендлеры → сервисы → репозитории.
  - `FolderRepo.FindAll` / `LayoutRepo.FindAll` теперь фильтруют по `userId`.
  - Добавлены проверки владения (`ErrFolderForbidden` / `ErrLayoutForbidden`) в `GetByID`/`Update`/`Delete`, маппятся в `404` (как у проектов).
  - Удалён мёртвый `handlers/defaults.go` и небезопасный неиспользуемый `FolderRepo.FindByParentID`.

### 2.2 Порядковый номер проекта
- **Проблема:** бэкенд не присваивал `number`/`template`, поэтому карточка проекта показывала «`undefined #undefined`».
- **Исправление:** в `ProjectService.Create` добавлено присвоение порядкового `Number` в рамках пользователя (через новый `ProjectRepo.CountByUser`).
- **Связанный баг:** автосейв редактора шлёт `roomData`/`name`/`status`, но **не** `number`/`template` — старый `Update` затирал их в `nil`. Теперь `Update` перезаписывает `Template`/`Number` только если они явно пришли в запросе.

### 2.3 Сборка дерева папок (латентный баг)
- **Проблема:** `FolderService.GetTree` присоединял к родителю **копии** узлов до того, как к ним добавлялись потомки. При произвольном порядке выдачи Mongo это **теряло вложенные папки** глубже первого уровня.
- **Исправление:** логика вынесена в чистую функцию `buildFolderTree` на промежуточных указателях с финальной рекурсивной конвертацией — корректна при любом порядке и глубине; «осиротевшие» папки трактуются как корневые. Покрыта тестами.

### 2.4 Отладочный вывод
- Удалены `fmt.Printf`-логи из `project_handler.go` (Update) и неиспользуемый импорт `fmt`.

### 2.5 Тестируемость (рефакторинг)
- Зависимости сервисов от репозиториев переведены на **интерфейсы** (объявлены на стороне потребителя — идиоматичный Go), что позволило подменять их фейками в тестах. Конкретные репозитории по-прежнему удовлетворяют интерфейсам, `main.go` не менялся по смыслу.

### 2.6 Тесты (было 0)
Добавлено 40+ юнит-тестов, `go test -race ./...` зелёный:
- `internal/auth/jwt_test.go` — генерация/парсинг JWT, протухание, чужой секрет, подмена, мусор.
- `internal/config/config_test.go` — дефолты и переопределения env, режимы SMTP.
- `internal/models/user_test.go` — `ToPublic` (не утекает `PasswordHash`).
- `internal/services/*_test.go` — флоу кода подтверждения (регистрация/логин, протухание, неверный код), присвоение номера проекта, сохранение номера при автосейве, проверки владения для проектов/папок/макетов, сборка дерева папок, изоляция списков по пользователю. Фейки репозиториев — в `fakes_test.go`.

## 6. Полное сохранение сессии, движение и редизайн

### 6.1 Автосейв не срабатывал в 3D (главный баг сохранения)
- **Причина:** `FPSControls` каждый кадр (~60/с) вызывал `onPositionChange`/`onRotationChange`, которые диспатчили в Redux → состояние редактора менялось каждый кадр → дебаунс-таймер автосейва (`setTimeout(save, 3000)`) сбрасывался каждый кадр и **никогда не срабатывал**. В 3D-режиме (где пользователь и работает) не сохранялось ничего: мебель, свет, размеры. В 2D сохранялось.
- **Исправление:**
  - Позиция/поворот персонажа теперь пишутся в `ref` (без ре-рендеров), а не в Redux.
  - Автосейв переписан на надёжную модель: периодическое сохранение раз в 3с, **только если состояние изменилось** (сравнение снимка), + финальный сброс при выходе из редактора и `beforeunload`. Не зависит от частоты ре-рендеров.
- Теперь персистится **всё**: размеры комнаты, цвета, освещение, проёмы, перегородки, мебель (масштаб/позиция/поворот), позиция и камера персонажа.

### 6.2 Камера/позиция не восстанавливались
- `FPSControls` всегда стартовал из начала координат, игнорируя сохранённые значения. Добавлено восстановление позиции и поворота камеры из сессии при монтировании (через `initialPosition`/`initialRotation`, прокинутые из `ProjectEditorPage` → `EditorScene`).

### 6.3 Движение: спринт, прыжок, присед
- `Shift` — бег (был), **`Space` — прыжок** (импульс + гравитация), **`Ctrl`/`C` — присед** (плавное понижение высоты глаз + замедление). Защита: клавиши не перехватываются при фокусе в полях ввода; `Space` не скроллит страницу; при потере фокуса вкладки зажатые клавиши сбрасываются. Подсказка управления на сцене обновлена (чипы-клавиши).

### 6.4 Редизайн UI до уровня продукта
- Единая дизайн-система в `app/styles/index.scss`: токены (бренд-градиент, поверхности, текст, радиусы, тени, кольца фокуса, отдельная тёмная палитра редактора), фон с мягкими градиентами, аккуратные скроллбары, анимации появления.
- Переоформлены: общий хедер (стеклянный, бейдж + вордмарк), сегментированная навигация страниц, карточки проектов/папок/макетов (градиентные обложки, читаемый контраст, hover-подъём, адаптивная сетка `auto-fill`), строка поиска, FAB, все модалки (создание проекта/папки/макета, авторизация — backdrop-blur, кольца фокуса, бренд-кнопки), контекстные меню карточек, FolderPicker, лоадер.
- **Тёмный «хром» редактора**: header, sidebar (вкладки + инструменты + сетка мебели), панель свойств — профессиональная тёмная тема.

## 7. Доводка до VR-конструктора интерьера (MVP)

### 7.1 VR / WebXR (главная фича)
- Подключён `@react-three/xr` v6. Кнопка **«🥽 VR»** в шапке редактора: проверка `navigator.xr.isSessionSupported('immersive-vr')`, понятное сообщение, если VR недоступен; `store.enterVR()`.
- 3D-сцена обёрнута в `<XR>`, добавлен `XROrigin` + телепорт по полу (`TeleportTarget`, стик контроллера → луч → телепорт). Лучи контроллеров и выбор предметов — штатными pointer-событиями.
- `FPSControls` корректно «отключается» в VR-сессии (`gl.xr.isPresenting`) — камерой управляет шлем, перемещение телепортом. Десктоп-ходьба не сломана.
- Рендерер настроен под VR: `dpr` ограничен `[1, 1.75]`, ACES tone mapping, тени `PCFShadowMap`, лёгкие процедурные текстуры — ориентир на автономный PICO/Quest.
- Сборка `tsc -b` спотыкалась о пакет xr (нет поля `types`) — `build` переведён на `tsc --noEmit && rsbuild build`.

### 7.2 Локальное сохранение/загрузка (F7)
- Сервис `shared/lib/projectFile.ts`: сериализация полного снимка (размеры, цвета, **материалы**, проёмы, перегородки, мебель, позиция/камера) в JSON, экспорт в файл, импорт с валидацией.

## 11. Аудит безопасности и устойчивости (ноябрь 2026)

### 11.1 Авторизация и коды подтверждения
- **Попытки ввода кода расходуются атомарно** (`FindOneAndUpdate` с условием `attempts < 5`) до сравнения
  кода: параллельные запросы больше не получают лишних проверок (раньше счётчик увеличивался после сравнения).
- **Токен заявки на регистрацию**: ответ на отправку кода содержит случайный токен (в базе — только SHA-256);
  код подтверждается только вместе с ним. Тот, кто перезаписал чужую незавершённую регистрацию, не создаст
  аккаунт с чужим паролем, а владелец почты не «подтвердит» чужой пароль.
- **Смена почты требует текущий пароль** — украденного токена сессии недостаточно, чтобы увести аккаунт.
- **Блокировка перебора паролей**: 10 неудачных входов на адрес за 15 минут (и проверок пароля на пользователя);
  для несуществующих адресов выполняется сравнение с фиктивным хэшем — время ответа не выдаёт, есть ли аккаунт.
- Пароль: от 6 символов (считаются символы, не байты) до 72 байт (больше bcrypt не учитывает); имя — до 60 символов.
- JWT: принимается только HS256 и только с `exp`; секрет — не короче 32 байт и не «заглушка».

## 15. Этажи, лестницы и вид с улицы (ноябрь 2026)

- **Этажи.** Проект — здание до пяти этажей. У каждого этажа свои размеры и смещение (новый этаж
  повторяет контур верхнего), внешние и внутренние стены, проёмы и двери, помещения, свет и мебель.
  Активный этаж «живёт» в прежних слайсах `editor` и `furniture`, поэтому все команды, 2D-план,
  инспектор и VR работают с ним без переделок; остальные этажи — в новом слайсе `building`.
  Смена, добавление и удаление этажа — одно действие для всех трёх слайсов: документ не бывает
  «наполовину переключён», смена этажа не попадает в историю и не запускает сохранение.
  Переключатель этажей — на сцене и на плане (добавить, переименовать, удалить с подтверждением,
  выбрать для редактирования). При перетаскивании стены этаж смещается в здании так, что
  неподвижная стена и мебель остаются над этажом ниже.
- **Перекрытия.** Между этажами — плита (снизу потолок нижнего этажа, сверху чистовой пол верхнего),
  торцы видны по фасаду. Крыша нижнего этажа, не закрытая верхним, — терраса со стеклянным
  ограждением; у верхнего этажа — плоская крыша с ограждением.
- **Лестницы.** Прямой марш или марш с площадкой — инструментом «Лестница» (призрак под курсором,
  R — поворот на 90°) или из каталога. Число и высота подступёнков, проступь (2h + b ≈ 63 см)
  и длина марша считаются от высоты подъёма; тетивы, поручни на стойках, стеклянное ограждение
  выреза наверху. Вырез в перекрытии появляется сам; мебель не встаёт на марш и в проём.
  В 2D — марш со ступенями и стрелкой подъёма, проём над лестницей снизу — пунктиром.
- **Хождение по этажам.** От первого лица и в VR по лестнице поднимаются и спускаются: опора —
  самая высокая поверхность не выше ступней + 35 см (ступени, полы, терраса, участок), взгляд
  плавно догоняет ступени, с края — падение; препятствия с диапазоном высот — стены и мебель
  этажа под ногами, косоуры и ограждения. Этаж, на котором стоит человек, становится активным
  (свет, двери и правки — его). В VR телепорт работает на пол любого этажа и на участок.
  Шаг от первого лица делится на подшаги по 1/30 с: скорость ходьбы, подъём по ступеням и прыжок
  не зависят от частоты кадров — и на слабой машине без видеокарты человек идёт в реальном времени.
- **«Улица».** Новый режим камеры рядом с «Облёт / От лица / План»: облёт здания снаружи — все
  этажи, стены у камеры не срезаются, видны перекрытия, террасы и крыша; камера не подлетает
  внутрь. С улицы от первого лица начинают перед фасадом и обходят здание по участку. В облёте,
  на плане и в фикс-видах этажи выше активного скрыты, камера переезжает вместе с этажом.
- **Документ v4.** `floors` (этажи с лестницами `stairs`) и `slabThickness`; v1/v2/v3 мигрируют
  в один этаж без потерь, повреждённые части этажей отбрасываются по одной. Бэкенд проверяет
  этажи (1–5), лимиты массивов и размеры каждого этажа, до 8 лестниц на этаж и толщину перекрытия.
- **Шаблон «Двухуровневый пентхаус» (бывший «Апартаменты 150 м²»).** Нижний уровень 15 × 10 м:
  гостиная-кухня-столовая с лестницей вдоль стены, гостевой санузел, панорамный балкон. Верхний
  15 × 7 м отступает от фасада на 3 м: холл со световым проёмом лестницы, коридор, кабинет,
  мастер-спальня, спальня и ванная, стеклянные двери на террасу над балконом. 255 м², 2 этажа.
- **Сохранение и история.** Статус «Есть изменения» ставится сразу при правке (раньше — через 0,4 с
  вместе с локальной копией), поэтому закрытие вкладки сразу после правки её не теряет. Отмена
  и повтор правки на другом этаже делают его активным — правка не отменяется «невидимо».
  Толщина перекрытия не меняется, если какой-то лестнице не хватит места; при изменении размеров
  этажа мебель не выталкивается в проём лестницы снизу; при установке лестницы под мебелью
  или стеной этажа выше — предупреждение. Лимит документа сцены на бэкенде — 3 МБ.
- Тесты: 870 фронтенд-тестов (≈ 98,8 % строк) — этажи, перекрытия, прямоугольники с вырезами,
  раскладка ступеней, подъём и спуск по лестнице, миграция v3 → v4, команды этажей и лестниц,
  отмена добавления этажа; Go-тесты лимитов документа v4; E2E «этаж → лестница → мебель наверху →
  перезагрузка → подъём от первого лица → улица» и открытие старого одноэтажного проекта.

## 16. Подушки на диванах и предметы на стенах и потолке (ноябрь 2026)

- **Подушки на диване (п. 9 ТЗ).** У диванов и кресел — посадочные места для подушек: у спинки
  (подушка нижней задней кромкой касается спинки и опирается на неё с наклоном места: 15° у
  дивана, 25° и 30° у откинутых кресел) и на сиденье (подушка лежит). Места описаны в манифесте
  каталога (`sockets`) по замерам геометрии моделей, у изогнутого бархатного дивана — вдоль
  спинки с поворотом; у своих моделей и старого «Дивана (базовый)» места раскладываются по
  габаритам между подлокотниками. Подушка, брошенная или перетащенная на диван (луч указателя
  на высоте сиденья, точка на плане, VR-меню), садится в ближайшее свободное место; свободные
  места подсвечиваются голубым, занятые — серым, а если мест нет — призрак красный. Подушки
  мягкие: касание соседей на пару сантиметров не считается столкновением. Диван — опора
  подушки: переносит и поворачивает её с собой, при масштабе пересаживает в те же места, при
  удалении снимает на пол. Подушку можно довернуть в месте на ±35°, снять на пол, дублировать
  в соседнее место. Наклон хранится в `rotation[0]`, место — в новом поле мебели `socket`;
  старые проекты не меняются. В каталоге — две новые процедурные подушки (бархатная 45 × 45,
  льняная 40 × 40), набор «Декоративные подушки» садится к спинке без доп. наклона.
- **Настенные и потолочные предметы (п. 10 ТЗ).** У каждой модели каталога в манифесте тип
  крепления `attach` (`floor` / `wall` / `ceiling` / `surface`) и у настенных — высота центра
  `mountHeight`; свои модели узнаются по названию («настенный», «картина», «бра», «люстра», wall,
  sconce, chandelier…). Настенный предмет вешается на грань стены: внутренние грани внешних стен
  (кроме удалённых) и обе грани перегородок. Грань выбирает луч указателя (3D, от первого лица,
  VR) — для этого при размещении указатель ловит невидимая «коробка» комнаты изнутри — или,
  на плане и с клавиатуры, ближайшая стена не дальше 1,2 м. Предмет прижат задней стороной к стене
  с зазором 4 мм, фасадом в комнату; новый — на высоте из каталога, при перетаскивании схваченная
  точка остаётся под курсором вдоль стены и по высоте. Он не выходит за торцы и выше стены,
  обходит проёмы окон и дверей и мебель (с учётом высоты: картина висит над диваном, а у шкафа
  сдвигается вдоль стены). Без стены рядом или без места положение недопустимо: призрак красный,
  команда отказывается с сообщением. Потолочный предмет висит верхом у потолка. Стена под
  предметом и место на ней подсвечиваются, у потолочного — потолок над ним. Где висит предмет,
  хранится в новом поле мебели `mount` (грань стены или `ceiling`): после перемещения или
  удаления перегородки и изменения размеров и высоты комнаты предмет пересаживается на свою
  стену (удалена — на ближайшую) или под новый потолок; старые проекты не меняются. Настенная
  полка — ещё и опора: ваза на ней едет вместе с полкой. Новые процедурные модели — полка из дуба
  на кронштейнах и сплит-кондиционер.
- Ручной чек-лист с шагами воспроизведения — `docs/manual-checklist.md`.
- Тесты: 952 фронтенд-теста — места подушек, наклон и посадка, тип крепления, грани стен, подвес
  с проёмами и мебелью, команды подушек и подвеса (в том числе после правки стен); E2E «подушка
  на диване» и «постер на стене, люстра под потолком».

## 17. Восстановление пароля (ноябрь 2026)

- **«Забыли пароль?»** — ссылка в окне входа. Почта → код из письма (та же отправка, что при
  регистрации: Brevo, Resend или SMTP; в разработке и CI с `SMTP_LOG_ONLY=true` — строка `[CODE]`
  в логе бэкенда) → код и новый пароль дважды → окно входа с той же почтой и сообщением
  «Пароль изменён. Войдите с новым паролем.». Сам сброс в аккаунт не входит: вход — обычным
  способом (так советует OWASP). API: `POST /api/auth/password/send-code` и `/api/auth/password/reset`.
- **Ответ не выдаёт, есть ли аккаунт.** Запись кода создаётся и для адреса без аккаунта, поэтому
  текст ответа, пауза 30 с перед повтором и попытки ведут себя одинаково; письмо уходит только
  владельцу аккаунта. Код сверяется всегда (время ответа то же), а для адреса без аккаунта даже
  угаданный код ведёт себя как неверный.
- **Код:** живёт 10 минут, одноразовый (запись забирается `DeleteOne({_id, codeHash})` — из
  параллельных подтверждений проходит одно), 5 попыток на код (атомарно), и 10 неверных кодов на
  адрес за час по всем выданным кодам — перебор не обойти, запрашивая новые коды. Лимит по IP —
  общий с остальными кодами (10 в минуту). Код действует, только пока у аккаунта та же почта.
- **Новый пароль** — по правилам регистрации (от 6 символов до 72 байт: одна схема на фронтенде,
  `validatePassword` на сервере); проверяется до кода, поэтому попытка не тратится; хэш считается
  до того, как код забран. После смены пароля снимается блокировка входа за неудачные попытки.
- **Прежние сессии закрываются.** У пользователя — версия сессий `tokenVersion`, в JWT — `ver`;
  middleware сверяет её с базой на каждом защищённом запросе (один `FindOne` по `_id` с проекцией)
  и отвечает 401 на токен со старой версией или удалённого пользователя. Сброс пароля меняет хэш
  и увеличивает версию одним запросом. Старые токены без `ver` и пользователи без поля — версия 0:
  выкатка никого не разлогинит.
- **Компромиссы и ограничения.** Счётчик неверных кодов, как и блокировка входа, — в памяти
  процесса (на реплику, сбрасывается при перезапуске). Тот, кто знает чужую почту, может неверными
  кодами закрыть для неё сброс на час — плата за защиту от перебора с разных IP (как у блокировки
  входа). Регистрация по-прежнему сообщает «Эта почта уже зарегистрирована». Вкладка с отозванной
  сессией выходит из аккаунта по первому же ответу 401, без обновления страницы (раздел 18).
  Если сервер запущен с `ALLOW_LOG_ONLY_MAIL=true`, коды сброса, как и коды регистрации,
  попадают в лог сервера.
- Ручной чек-лист — раздел 11 в `docs/manual-checklist.md`.
- Тесты: Go — сервис сброса (одинаковый ответ, письмо только владельцу, пауза, попытки и лимит по
  адресу, одноразовость и параллельные подтверждения, смена почты, блокировка входа, ошибки
  хранилища), репозитории на настоящей MongoDB (`UpdatePassword` с версией сессий, атомарный
  `Claim`), обработчики, роутер (отозванная сессия на всех защищённых маршрутах, общий лимит кодов),
  middleware и JWT; фронтенд — схема пароля, слайс, саги, DOM-тест окна (шаги, ошибки, отсчёт
  повторной отправки); E2E `password-reset.spec.ts` — свой аккаунт через API, коды из лога бэкенда:
  неверный код, смена пароля, старая сессия и старый пароль — 401, вход с новым паролем.

## 18. Выход при конце сессии (ноябрь 2026)

- **Было.** После сброса пароля сервер отвечает 401 на старые токены, но общего обработчика на
  фронтенде не было: вкладка с отозванной сессией оставалась «вошедшей» (`isAuth: true`), фичи
  показывали каждая своё («Сессия истекла — войдите снова», «Войдите в аккаунт, чтобы открыть
  проект», «Не удалось сохранить на сервер…»), а выходила вкладка только при обновлении страницы
  (`restoreSession`).
- **Где ловится.** `request()` в `src/app/api/client.ts`: 401 с ответом авторизации сервера
  (`invalid or expired token`, `authorization required`, а также `invalid authorization header`
  и `unauthorized` — `isSessionRejection` в `src/app/api/session.ts`) на запрос, ушедший
  с сохранённым токеном, — конец сессии: у ошибки `sessionEnded = true`, а `rejectSession(token)`
  стирает токен и сообщает подписчикам, только если сохранён всё ещё этот токен. Параллельные
  отказы (проекты, папки, шаблоны, автосохранение) дают один выход, а ответ на старый запрос после
  нового входа новую сессию не трогает. Запросы без токена (вход, регистрация, сброс пароля),
  401 с другим смыслом у защищённых запросов (неверный код при смене почты) и 401 без JSON (прокси)
  сессию не заканчивают.
- **Выход.** Сага пользователя подписана на конец сессии (`eventChannel`, события по очереди):
  `logout()` — как по кнопке «Выйти» — и одно сообщение «Сессия завершена — войдите снова» (6 с);
  `restoreSession` при отказе сервера второго выхода не делает. `apiErrorText` отвечает на такие
  ошибки тем же текстом, тост с текстом, который уже на экране, не повторяется, а сохранение проекта,
  переименование, шаблон из редактора, откат папок и окно новой папки своих сообщений при конце
  сессии не показывают. Окно новой папки и окна профиля при выходе закрываются.
- **Другие вкладки.** Токен в localStorage общий для вкладок: стёртый в одной (выход или конец
  сессии) приходит в остальные событием `storage`, и вкладки с входом тоже выходят. Вход в другой
  вкладке здесь сессию не открывает — до входа или обновления страницы остаётся гостевой вид.
- **Редактор.** Сага сессии проекта на любой `logout` сразу пишет несохранённые правки в локальную
  копию (`synced: false`, как при закрытии вкладки: без входа на сервер не сохранить), очищает сцену
  и переводит сессию в статус `signedOut`. Страница показывает «Войдите, чтобы открыть проект»
  (и строку о несохранённых изменениях, если копия не синхронизирована), кнопки «Войти»
  и «Вернуться к проектам». После входа (`setUser`) проект открывается снова: копия новее серверной
  версии — она загружается и досохраняется. Так же выглядит проект, открытый по ссылке без входа
  (раньше — ошибка открытия).
- **Гонки.** Ответ на открытие или сохранение, пришедший после выхода или закрытия проекта,
  состояние не меняет: сцена не загружается, проект не возвращается в список, копия не отмечается
  синхронизированной (в ней могут быть правки новее этого сохранения). Повтор сохранения после сбоя
  сети без входа не уходит.
- **Тесты.** Юнит — клиент API (отказ с токеном, параллельные отказы, вход и сброс без токена, 401
  с другим смыслом, новый вход во время запроса, ответ без JSON, 403), `session.ts` (другая
  вкладка), тексты ошибок, тосты без повторов; интеграция — сага пользователя (один выход и одно
  сообщение, восстановление сессии при загрузке, другая вкладка), сага сессии проекта (копия правок,
  `signedOut`, открытие после входа и досохранение, 401 при открытии, гонки открытия, сохранения
  и повтора), папки, `resetDataSaga`; DOM — «Войдите, чтобы открыть проект». E2E
  `session-revoked.spec.ts` на своих аккаунтах (сброс пароля по API, код из лога бэкенда): главная —
  звезда «В избранное» после смены пароля → гостевой вид и одно сообщение; редактор — проект по
  ссылке без входа, вход, смена пароля, правка ширины → выход по 401 автосохранения, копия на
  устройстве, вход с новым паролем → проект открыт с правкой, и она на сервере. Помощники E2E
  повторяют запросы кодов после 429: лимит 10 кодов в минуту на IP общий для всех сценариев.
